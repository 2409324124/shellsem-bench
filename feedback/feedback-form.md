# 评测反馈表填写内容

## 评测使用的 Agent / Harness
Pi Coding Agent 0.85.1（通过 SDK 使用 read/write/edit/bash，自定义 Docker 工具执行适配器）；另设直接调用已配置 API、无工具、无 Pi 的裸模型对照。Codex 用于搭建评测、监测和整理结果，不是被评测模型。

## 操作系统
Ubuntu 24.04.3 LTS（Linux）；被测 Shell 为 GNU Bash 5.2.37。Docker 容器限制 1 CPU、512 MiB 内存、128 PID，保持联网并启用 --init。

## 评测任务所属领域
软件工程 / 编程 / Shell 脚本 / Agent 工具使用与运行可靠性。

## 评测任务说明
比较旧模型 qwen3.8-max-0902 与新预览模型 qwen-latest-series-invite-2608，在裸模型和 Pi 工具环境下完成两道 Bash 任务的表现。

Q1：推导两个 Bash 脚本变体的 stdout、stderr 和退出码，覆盖 ERR、errexit、local、子 Shell、FD 和 lastpipe。设计目的是检验复杂执行语义，以及工具执行能否纠正输出推导。

Q2：修复流式 NUL 记录处理函数 collect()，要求参数与二进制输出保真、真实退出状态和优先级正确、stdin/FD 隔离、直接调用与 if 条件调用均正确。设计目的是检验异常路径、资源处理和自测覆盖能力。

Q2 使用 16 个场景 × 两种调用位置，共 32 项。每项适用的输出、状态、报告、参数和隔离检查全部通过才得 1 分。解释错误不计为错误，不因解释篇幅或展示方式扣功能分；代码约束仍检查。

## 评测任务附件
上传 task-attachments.zip：原题、裸模型/Pi 提示词、输入清单及环境记录。

## 整体体验评价
总体较好，新模型在本次 Shell 编程任务上优于旧模型。裸模型 Q1 两者均为 0/2；Pi Q1 两者均为 2/2。Q2 裸模型旧 0/32、新 28/32；修正运行环境后的 Pi Q2 旧 0/32（补充运行 6/32），新 32/32。

新模型借助工具能得到通过全部功能检查的实现，但过程中出现过重复试验。初期还发现了上下文预算耗尽、压缩保留量不合适、容器僵尸进程积累等 harness 问题。修正后才完成对照，不能将早期基础设施失败直接当作模型能力失败。
