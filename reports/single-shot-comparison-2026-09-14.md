## 题目、条件与判分

Q1 要求推导两个 Bash 脚本的 stdout、stderr、退出码，再解释 ERR、errexit、local、lastpipe、子 Shell 与描述符的作用。Q2 要求修复流式 NUL 记录处理函数：正确调用 scanner/worker、保持二进制输出、取得真实退出状态、隔离 stdin/描述符、按优先级返回，并兼容直接调用及 if 条件调用。

裸模型每模型每题一个独立单消息 API 请求，无 Pi、无 tools、无历史及反馈，关闭思考，输出上限 8192，串行运行。4 份首答来自 5 次请求：预览 Q2 首次 120.848 秒网络超时、未取得回答；单独目录补请求后取得首答。没有重发已有答案的题目，没有替换原始首答。题面哈希见 single_shot/manifest.json。

Pi 0.85.1 使用相同模型、相同语义要求，关闭思考，开放 read/write/edit/bash；提示词只放开验证工具、说明工作目录/版本并要求 Q2 保存 collect.sh。每题生成上限 300 秒、100 次工具调用，每次回复最多 8192 token；瞬时 API 故障最多两次退避重试，计入时间。隐藏判分数据和参考解均未提供给模型。四项串行运行，各自独立容器与会话。

使用现有 Docker 镜像，不拉镜像；1 CPU、512 MiB、128 pids、桥接联网。注入独立编译的 Bash 5.2.37，不替换系统 Bash，不挂载密钥。版本、源码/二进制哈希见 single_shot/environment.json。

Q1 两变体各执行 50 次确认结果稳定。对首答中所有 JSON 块逐项保留比较；两份裸模型首答中的所有版本都不正确，stderr 空和退出码 0 正确，stdout 错误。Q2 提取首答最后一个完整 collect 代码块，不修复代码；16 组独立数据 × 直接/if 两种调用方式，共 32 项。独立参考函数先通过全部 32 项。用户提及的原始参考包未提供，本次没有冒用原包结果。功能检查与源码约束、解释审阅分开记录。

## 实际发现的问题

裸模型预览 Q2 的四个失败均为直接调用下 worker 非零：worker_failure、all_errors、framing_over_worker、worker255。未受条件保护的 worker 触发 errexit，使 rc=$?、后续工作和报告来不及执行；if 模式 16 项全部通过。固定 FD 4 覆盖调用者既有 FD 的潜在问题未计入上述分数。

裸模型基准 Q2 存在 scanner stdin 未隔离、状态丢失、误读调用者 stdin、worker 继承 scanner FD 等问题；关闭 stdin 与提供可读 EOF 不等价，错误信息还会破坏 stderr 保真。

Pi Q1 两模型精确输出均正确，解释均不通过。预览错误声称 local 返回 4，并错误解释 f 的 ERR 抑制；基准误称第二次 g 整体以 4 失败。正确关系是 f 的条件上下文抑制相关 errexit/ERR，g 中 local 的状态掩盖命令替换的非零状态。读取实际输出并不保证模型理解执行原因。

Pi 预览 Q2 中间代码使用题目禁止的 eval，把 worker stdout 转到报告 FD 3，未隔离 scanner 读 FD，并错误处理尾片段及 wait。Pi 基准 Q2 中间代码保留了多次 scanner 调用，以可能与合法记录冲突的哨兵传退出码，泄漏描述符，并用 exec 重定向改变调用者 stderr；32 项均未完整通过。

预览 Q1 的 502 与请求超时经重试恢复。Q1 工具错误包括环境中不存在的 Python/Python3、缺失 Perl 模块及能力探测失败。工具错误事件数不等于语义误用数；故意失败的自测和能力探测也可能非零退出。裸模型无工具调用，不能把其工具正确率定义为零。

观察器、心跳、逐次请求与工具事件、资源状态、独立 guard 共同提供运行可见性；两次未交付均有明确终止原因，不是无法定位的静默卡死。它们不能保证自动发现所有语义错误，语义问题仍由独立判分及源码审阅识别。运行器也已修正“无最终回答却标记 captured”的状态问题，原始生成结果另存 generation-result.json。

## 结论边界及证据

本轮展示了工具访问与 Pi 执行循环的联合效果：精确输出题明显改善，解释和复杂函数任务没有达到完整正确交付。只有两题、每条件一次，不能可靠排名模型，也不能给出 harness 因果影响的百分比。工具访问、多轮反馈、Pi 系统提示和总计算预算同时变化；要隔离 harness，需要在相同工具、提示与预算下增加最小执行循环或其他 harness 对照。
